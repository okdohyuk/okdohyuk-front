# 단축 URL 생성 보상형 광고

생성 화면에서 광고 시청에 동의한 사용자가 보상을 받으면 단축 URL을 1개 생성합니다.
이미 생성된 `/l/{code}` 링크는 광고 없이 기존대로 이동합니다.

## 연결 설정

일반 AdSense `ca-pub-...` 게시자 ID나 디스플레이 슬롯 대신 **Google Ad Manager 웹 보상형 광고 단위**가 필요합니다.
프론트엔드 빌드 환경에 실제 광고 단위 경로를 설정하고 다시 빌드합니다.

```dotenv
NEXT_PUBLIC_SHORT_URL_REWARDED_AD_UNIT=/YOUR_NETWORK_CODE/YOUR_REWARDED_AD_UNIT
```

위 경로는 형식 예시이며 실제 값으로 교체해야 합니다. 운영에 Google 샘플 광고 단위를 넣지 마세요.
환경변수가 비어 있으면 기존의 광고 없는 생성 흐름을 유지합니다. 값이 지정됐지만
광고를 로드하지 못하면 생성으로 자동 우회하지 않고 재시도/취소를 안내합니다.
웹 보상형은 기본적으로 영상과 디스플레이 수요를 모두 받습니다. 영상만 표시하려면
Ad Manager 담당자를 통해 해당 인벤토리의 디스플레이 수요 차단 설정이 필요합니다.

## 동작과 검증 범위

- URL/만료 설정을 고정한 뒤 광고를 준비합니다. 사용자가 시청 버튼을 눌러야 광고가 표시됩니다.
- `rewardedSlotGranted` 수신 후 `rewardedSlotClosed`가 발생하면 고정한 요청을 1회 전송합니다.
- 영상 종료 이벤트, 광고 닫기, 시간 경과만으로 보상을 승인하지 않습니다.
- Google 문서상 일부 광고는 영상이 끝나기 전에 보상을 지급합니다. 따라서 이 흐름의
  완료 기준은 Google의 보상 승인이고, 모든 영상의 마지막 프레임까지 시청했다는 의미는 아닙니다.
- 보상 없이 닫기, 미지원 기기, 광고 미송출, 스크립트 오류/차단은 링크를 생성하지 않습니다.
- 생성 API가 실패하면 같은 URL/만료 설정의 재시도에는 이미 획득한 보상을 재사용합니다.
  성공 후 다음 생성 또는 입력이 달라진 요청에는 새 광고가 필요합니다.
- 페이지 이탈/취소 시 이벤트와 슬롯을 정리하며 늦게 도착한 이벤트는 무시합니다.
- GPT가 허용하지 않는 동시 보상형 광고 요청을 방지합니다.

이 기능은 브라우저 생성 화면의 흐름 제어입니다. Google은 **웹 보상형 광고의 서버 측
시청 검증을 지원하지 않습니다**. 공개 생성 API를 직접 호출하는 클라이언트나 브라우저를
변조한 요청까지 차단하는 결제/권한 장벽이 아니며, 클라이언트가 보낸 값을 서버 검증
증명으로 취급하지 않습니다. 그런 보장이 필요하면 서버 검증을 제공하는 광고 공급사가 필요합니다.

실제 광고 송출 여부는 계정/광고 단위/재고/사용자 환경에 달려 있습니다. 자동 테스트는
Google 이벤트를 모의하며 실제 광고를 시청하거나 보상 수익을 발생시키지 않습니다.
기존 Google 개인정보/동의 관리 설정은 배포 인벤토리에 맞게 운영해야 합니다.
